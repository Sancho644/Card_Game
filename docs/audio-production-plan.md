Unity 6000.6.7f1 · ветка `feature/audio-polish` · базовый коммит `3186ec8da33c4c39c0b922fd64632795f4c483fa`.

## 1. Исходное состояние до Audio Runtime Preparation

**Звуковые вызовы есть у 17 из 19 событий. Назначенных клипов 0 из 19.** В проектном каталоге `Assets` Unity AssetDatabase показала 0 `AudioClip` и 0 `AudioMixer`. Аудит основан на коде и сериализованных данных `origin/main`. Проверка открытого редактора через MCP подтвердила пустой каталог клипов и микшеров, `MasterVolume = 1` и один активный слушатель в сцене `Bootstrap` вне Play Mode.

| Участок | Что есть и что это означает |
|---|---|
| Данные | В `SoundCue.cs` 19 событий. `SoundEntry` хранит событие, ссылку на клип и индивидуальную громкость. В [SoundSettings.asset](../Assets/Data/Config/SoundSettings.asset) по одной строке для каждого значения, все `Clip` пустые, все `Volume` равны 1. Дубли ID отсутствуют, сравнивать назначенные клипы пока нечего. `Find` берёт первое совпадение, при отсутствии возвращает пустую запись. `OnValidate` добавляет пропуски, возможные дубли остаются. |
| Запуск | `Bootstrap.unity` ссылается на `SoundSettings.asset`. `AppRoot.Awake` помечает корень `DontDestroyOnLoad`, добавляет `AudioSourceSoundPlayer` и передаёт `ISoundPlayer` через `AppServices.Sound`. `SceneNavigator` загружает сцены в режиме `Single`. |
| Выпуск звука | `Configure` создаёт четыре 2D-источника с выключенным `playOnAwake`, без назначения групп микшера. `Play` пропускает незаданный клип без предупреждения. Для назначенного клипа выбирает источник по кругу и вызывает `PlayOneShot(clip, entry.Volume * settings.MasterVolume)`. Коэффициент применяется при запуске. Индивидуальная громкость и общий множитель по умолчанию сохраняют исходный уровень. |
| Параллельность | `PlayOneShot` позволяет клипам накладываться даже на одном источнике. Пул из четырёх источников сам по себе не ограничивает число голосов четырьмя и не предотвращает наложение повторов. В `AudioManager.asset` звук включён, задано 32 реальных и 512 виртуальных голосов, частота выбрана системой, сериализованное значение DSP-буфера 1024. Число источников для первой версии достаточно. Нагрузку и запас по пикам следует измерить с назначенными клипами. |
| Переходы | В `Bootstrap`, `MainMenu` и `Match` по одному включённому `AudioListener` на камере. В этих сценах и префабах сериализованных `AudioSource` нет. Источники на `AppRoot` переживают смену сцены, поэтому начатый эффект может доиграть. Уничтожение `AppRoot` уничтожает источники. Явного затухания или обрыва эффекта при смене сцены нет. |
| Музыка и UI | В `Assets` музыкальных клипов нет. В runtime-коде отсутствуют проигрыватель музыки и маршрутизация по группам. `UiButtons.Bind` и `CollectionUi.Button` привязывают действия без звука. Окно `SettingsModal` из `MainMenuLayout` содержит сложность ИИ и быстрые анимации. |

Воспроизведение нескольких клипов одним `AudioSource` соответствует поведению Unity. [Unity 6000.6 · AudioSource.PlayOneShot](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/audiosource/playoneshot)

### Повторы, отмена и очередь

- `MatchPresenter` один раз подписывается на `EventsProduced` и ставит эффекты видимых событий в очередь. В локальном матче источником служит `LocalMatchSession`. В сети `OnlineMatchSession` выдаёт события первого или более нового кадра. Ответ с прежней версией сам по себе их повторно не выдаёт. Звук игрового действия привязывать к принятому событию. Локальный звук выбора и UI-ответ на отклонение команды остаются отдельными. При скрытых картах звук сохраняет ту же приватность, что и игровой интерфейс.
- Пакет может содержать два правомерных выбывания, несколько розданных карт или два изменения силы. Сжимать частоту звуков в Presentation, не отбрасывая игровые события. Риск дублирования финальной заставки связан с повторным вызовом `MatchEndView.Show`. Аудит не воспроизводил такой повтор в матче.
- В `AnimationSettings` раздача идёт с интервалом 0,09 с, быстрый режим ускоряет DOTween в 2 раза, ускорение по нажатию — в 4 раза. События визуальной очереди могут сблизиться, длительность и тон клипов остаются прежними. Начальная политика для повторяющихся шорохов — 40–60 мс между стартами в реальном времени. Для однотипных сигналов силы — 80–120 мс. Подтвердить значения прослушиванием.
- Остановка очереди при уничтожении `MatchSceneRoot` снимает будущие шаги. Начатый one-shot на `AppRoot` может доиграть. При уходе с матча гасить длинные хвосты и музыку. При подтверждённом прерывании эффекта допустим отдельный `ability.cancel`. Действия и очередь должны завершаться одинаково при нулевой громкости и пустой ссылке на клип.


## 2. Звуковая карта

**Premium Dark Fantasy / Mythic Collectible Cards.** Карты звучат как плотная бумага с лёгким металлическим или каменным контактом. Магия добавляет короткие тональные жесты и фактуры стихии. Музыка держится на низких струнах, приглушённом металле и воздушных слоях. В частых действиях важны короткая атака и мягкий хвост. Смысл сохраняется на динамике телефона без глубокого баса.

**P0** — базовый набор для первого озвученного матча и меню. **P1** — полная обратная связь и характер игры. **P2** — варианты после проверки основной библиотеки. Длительности в секундах, включая естественный хвост. Отдельные ID могут ссылаться на один клип или на один материал с иной обработкой. Набор вариантов под одним ID начинается с 2–3 только для часто повторяющихся звуков.

### Способности и стихии

Базу выбирать по редкости только после принятого `AbilityPlayed`. Когда карта и её связь со стихией публичны, можно добавить один короткий стихийный слой. Универсальной способности подходит нейтральная база. У размещения и удаления карт оставить нейтральную фактуру. После публичного открытия поля редкий тематический акцент может использовать тот же стихийный слой, если он не перекрывает звук раскрытия. ## 3. Предлагаемая архитектура

| Компонент | Решение |
|---|---|
| `AppRoot` и `AppServices` | Сохранить действующее владение сервисами. В точке сборки сервисов передать проигрывателю эффектов группы микшера и добавить локальный проигрыватель музыки для переходов. Слушатель остаётся только у активной камеры сцены. |
| `ISoundPlayer` / `AudioSourceSoundPlayer` | Сохранить точку вызова и четыре 2D-источника для одноразовых эффектов. Начать с трёх источников на `SFX` и одного на `UI`, поскольку `PlayOneShot` микширует несколько клипов и на одном источнике. Добавить простое ограничение повторов для раздачи, UI и счётчиков. Приоритеты P0–P2 определяют очерёдность интеграции. Приоритет слышимости использовать отдельно — результат матча и значимый ход выше обычных шорохов. |
| Audio Mixer | Один asset с группой `Master` и дочерними `Music`, `SFX`, `UI`. Вывести четыре параметра громкости. Вызвать `SetFloat` после инициализации сцен, например в `Start`, и при изменении настройки. Индивидуальная громкость клипа остаётся дизайнерским коэффициентом. Текущий `SoundSettings.MasterVolume` оставить единичным либо сделать явным коэффициентом баланса при миграции. Пользовательский Master применяется только в микшере. |
| Music Player | Небольшой компонент на `AppRoot`. Первый запуск — источник петли и короткие заставки. Для утверждённого crossfade — два источника группы `Music` с управляемыми затуханиями. По переходам узнавать музыкальный контекст сцены. При быстром повторном переходе отменять предыдущий переход и вести источники к последнему состоянию. Один результат на матч. |
| Sound Settings / Audio Library | Сначала назначить клипы текущим `SoundEntry` и разрешить варианты там, где они нужны. ID звуковой карты служат ключами производства, сопоставление с cues остаётся явным. Длинные музыкальные треки можно хранить в небольшой отдельной конфигурации. Самостоятельный каталог библиотеки понадобится, если одна таблица перестанет описывать варианты, слои и лицензии. |
| AudioManager / Audio Pool | Существующий владелец сервисов и небольшой пул покрывают первую версию. Отдельный глобальный менеджер или универсальный пул ресурсов имеет смысл только после измеренного ограничения. |

`AudioMixer.SetFloat` меняет раскрытый параметр микшера, Unity рекомендует выполнять вызов после `Awake` или `OnEnable`. [Unity · AudioMixer.SetFloat](https://docs.unity.com/en-us/engine/6000.6/script-reference/unityengine/audio/audiomixer/setfloat)

### Проведение сигналов

- Анимационные звуки размещать в существующих презентационных шагах один раз в момент понятного визуального действия. Для `AbilityDiscard` проверять действительное движение в сброс. Для счётчиков исходить из показанной итоговой силы. Для окончания матча хранить признак сыгранной заставки с жизненным циклом матча, отдельно от повторного открытия окна.
- Существующие локальная и сетевая сессии остаются источниками событий. При отладке можно пометить вызов индексом события в пакете, номером пакета и ID сигнала. При повторном показе снимка стола воспроизводятся только новые видимые действия. В hot-seat смена фокуса на скрытую руку не выдаёт звук закрытой карты. На сервер или другой клиент аудиосигналы не отправляются.
- Для кнопок использовать семантический параметр в существующей привязке `UiButtons.Bind` и фабрике `CollectionUi.Button`. `Bind` удаляет предыдущие listeners, поэтому отдельный глобальный listener к каждой кнопке будет ненадёжен. В одном жесте достаточно одного осмысленного сигнала. Прослушивание UI не блокирует навигацию и не зависит от успеха игрового события, если оно озвучивает сам жест.

### Настройки игрока

Текущий `IPlayerSettingsService` сообщает об изменениях быстрых анимаций. `LocalPlayerSettingsService` использует `ISettingsStore`, а его реализация хранит целые в `PlayerPrefs`. Ту же схему можно расширить четырьмя процентами и признаком Mute. Стартовые значения для прослушивания ниже.

| Настройка | Старт | Ключ | Поведение |
|---|---:|---|---|
| Общая | 85% | `settings.audio.master` | Управляет всем миксом |
| Музыка | 55% | `settings.audio.music` | Меню, матч, итоговые музыкальные заставки |
| Эффекты | 85% | `settings.audio.sfx` | Карты, ходы, битвы и способности |
| Интерфейс | 75% | `settings.audio.ui` | Кнопки, выборы и окна |
| Без звука | выкл. | `settings.audio.muted` | Гасит Master, сохраняет значения всех ползунков |

В окне «Настройки» добавить блок «Звук» с процентами и Mute. При положительном значении переводить уровень в децибелы через `20 × log10(процент / 100)`, ноль и Mute устанавливают нижнюю границу −80 дБ. Правки слышны сразу. Сохранять `PlayerPrefs` по завершении жеста или при закрытии окна, чтобы не писать на диск с каждым движением ползунка. Короткий тестовый звук SFX и UI включать по завершении жеста или отдельному нажатию. При Mute предпрослушивание также выключено. Повторный запуск, переход сцены и выключение Mute восстанавливают выбранные уровни. Если настроек ещё нет, используются начальные значения.

## 4. Производственный формат и импорт

Мастера хранить в WAV PCM, 24 бит, 48 кГц. Карточные звуки, UI и компактные боевые сигналы начинать в mono. Музыку экспортировать в stereo. Для длинной магии stereo оставлять, если пространственная фактура сохраняет смысл при прослушивании в mono. Для Unity импортировать мастер или утверждённый WAV-экспорт из него. Vorbis ниже означает формат компрессии Unity на целевой платформе. Отдельный OGG нужен только для согласованной поставки, чтобы не перекодировать уже сжатый исходник.

| Материал | Windows x64 | Android | Условия проверки |
|---|---|---|---|
| Короткий SFX до 0,5 с | Mono, 44,1–48 кГц, PCM, `Decompress On Load`, `Preload Audio Data` | Mono, 32–44,1 кГц после сравнения, PCM, `Decompress On Load`, preload | Первая атака без задержки, высокие частоты и читаемость сохранены |
| Длинный SFX от 0,5 с | Mono либо обоснованное stereo, 44,1–48 кГц, Vorbis `Compressed In Memory`, качество `0,70–0,80` | Mono по умолчанию, 32–44,1 кГц, Vorbis `Compressed In Memory`, качество `0,60–0,75` | Редкие длинные хвосты могут загружаться заранее в фоне. Частые или чувствительные к задержке клипы оставить `Decompress On Load` после профилирования |
| Фоновая музыка | Stereo, 44,1–48 кГц, Vorbis `Streaming`, качество `0,70–0,80` | Stereo, 44,1 кГц, Vorbis `Streaming`, качество `0,55–0,70` | Проверить шов петли, асинхронную подготовку и стоимость двух потоков при crossfade. Не использовать Streaming для коротких эффектов |
| Частые повторы, включая раздачу и UI | Mono, 44,1 кГц, PCM `Decompress On Load`, preload | Mono, 32–44,1 кГц, PCM `Decompress On Load`, preload. ADPCM допустим после A/B для сухих шорохов при дефиците памяти | Сравнить щелчки, ВЧ и разборчивость вариантов. Короткие тональные сигналы оставить PCM при слышимых артефактах ADPCM |
| Итоговые музыкальные заставки | Stereo, 44,1–48 кГц, Vorbis `Decompress On Load` | Stereo, 44,1 кГц, Vorbis `Decompress On Load` | Прослушать первое срабатывание без паузы, затем сравнить память с `Compressed In Memory` |

`Preserve Sample Rate` подходит для утверждённого экспорта в нужной частоте. `Override Sample Rate` использовать только по результату сравнения Android-импорта. Флаг `Force To Mono` требует проверки уровня после суммирования каналов. Значения качества — отправная точка. Финальный выбор по слышимости и Audio Profiler. `Decompress On Load` убирает декодирование на старте за счёт памяти, `Compressed In Memory` расходует CPU при воспроизведении, `Streaming` добавляет буферы и работу потоков. [Unity 6000.6 · Audio Clip Import Settings](https://docs.unity.com/en-us/engine/6000.6/manual/audio/reference/class-audio-clip)

Начальный бюджет для профилирования — до 10 одновременно звучащих one-shot в плотном пакете и до двух музыкальных потоков на коротком переходе. Записать максимумы `Playing Audio Sources`, реальных голосов, `DSP CPU`, `Streaming CPU` и аудиопамяти. Проверить отсутствие треска при ускорении, читаемость счёта и отсутствие слышимого клиппинга. Для финального микса на стресс-сценарии ориентироваться на запас не менее 1 дБ до true peak 0 dBTP и проверять короткие атаки на динамике Android-устройства.

### Будущая структура

```text
Assets/Audio/
├── SFX/
│   ├── Cards/
│   ├── Battle/
│   ├── Abilities/
│   ├── Elements/
│   └── UI/
├── Music/
│   ├── MainMenu/
│   ├── Match/
│   └── Results/

```

`Sources/` предназначен для ведомости происхождения, прав и расположения мастеров. WAV-мастера, сессии и промежуточные экспорты держать вне Unity `Assets`, чтобы они не импортировались вторично. Для каждого звука в ведомости фиксировать ID, версию, длительность, источник, право использования и ссылку на мастер. Каталоги появляются при поставке соответствующих ресурсов.

| Этап | Объём | Критерии готовности |

Отменённый drag даёт только звук возврата после звука захвата. Отказ сервера не даёт звук контакта. Пробел в клипах не ломает анимации. Быстрая раздача читается. |
| 3. Сражения и способности | Подключить силы, исходы, ход, выбытие, типы редкости, отмену и стихии. Отдельно проверить именные Legendary. | Рост и падение различимы. Двойное выбытие, сохранение поля, возврат существ и эффекты отмены совпадают с визуальными событиями и журналом. Скрытые карты не выдают себя звуком. |
| 4. Музыка | Две петли, музыкальные итоги и простые затухания. Дополнительный слой после замеров основной версии. | Петли не щёлкают. Два быстрых перехода возвращают нужный трек. Коллекция продолжает меню. На каждый результат матча приходится один музыкальный сигнал. |
| 5. UI Sounds | Семантические звуки меню, коллекции, поиска, окон матча и смены настроек. | Мышь, клавиатура и touch дают один ожидаемый сигнал. Отключённый контрол не звучит как принятый. Карта, баннер и модальное окно не дублируют связанный SFX. |
| 6. Настройки громкости | Четыре группы, ползунки, Mute и сохранение. | Каждая группа изолирована. Громкость и Mute действуют сразу, включая активную музыку. После перезапуска настройки восстанавливаются. Полностью беззвучный матч проходит тем же путём. |
| 7. Финальное тестирование | Windows x64, физический Android, обычные и быстрые анимации, AI, hot-seat и два сетевых клиента. Профилирование и слушательские проверки. | Пройдены сценарии ниже. Нет новых аудиопредупреждений, повторов заставок, слышимого клиппинга или выпадений в профилированном сценарии. Результаты по памяти и CPU зафиксированы для обеих платформ. |

### Сценарии будущей проверки

- **Источники и жизненный цикл.** Открыть меню, коллекцию, поиск, матч, выйти, начать заново. Проверить один слушатель при загрузке каждой сцены, отсутствие дублей источников и остановку музыки матча. На Android сверить сворачивание, возврат и смену аудиоустройства.
- **Граница ввода и подтверждения.** Выбор, длинное нажатие, перетаскивание, неверная цель, быстрые повторные касания, отклонение команды и повторная доставка сетевого кадра. Для диагностики сверить очередь вызовов с версией события, аудио и кадрами видео.
- **Синхронизация.** Раздача, переворот поля, сброс способности, одновременное изменение двух сил, отступление, два выбывания, возвращение существ, победа, поражение и ничья. Пройти при обычной скорости, быстрых анимациях и ускорении нажатием. Проверить нормальный выход и выход во время очереди.
- **Микс и доступность.** Проверить Master/Music/SFX/UI, загрузку настроек и игру при Mute. Во всех случаях ход, результат и запрет понятны по существующему визуальному интерфейсу. Сверить матч на наушниках, обычных колонках и динамике Android.

В рамках аудита проверены ссылки в конфигурации, все вызовы `SoundCue` в коде, сериализованные слушатели и ресурсы открытого редактора. Измерения CPU и памяти, слышимая синхронизация, проверка переходов в Play Mode, Windows Player и Android относятся к этапу после подключения клипов. Следующий шаг после утверждения — подбор и прослушивание библиотеки P0.

## Audio Runtime Implementation

Аудит и карта звуков выше фиксируют исходное состояние и план производства. Реализация инфраструктуры сохраняет значения всех 19 `SoundCue` и допускает работу со всеми пустыми ссылками на клипы. Для интерфейса пользователя этот этап использует начальные значения **100%** на всех четырёх каналах. Целевые значения в производственном плане остаются ориентирами для последующего сведения.

| Участок | Реализация |
|---|---|
| Владение | `AppRoot` держит `AudioSourceSoundPlayer` и `MusicPlayer` между сценами. `ISoundPlayer` остаётся точкой входа для презентации. |
| Микшер | `Assets/Audio/Mixers/CardGameAudioMixer.mixer` → `Master` с дочерними `Music`, `SFX` и `UI`. Четыре исходных источника используют `SFX`, дополнительный источник использует `UI`, два музыкальных используют `Music`. |
| Уровни | `AudioMixerLevels` выставляет `MasterVolume`, `MusicVolume`, `SfxVolume` и `UiVolume`. Для ненулевого значения используется `20 × log10(x)`. При нуле значение микшера −80 дБ и соответствующие источники явно приглушены. При отсутствии группы или раскрытого параметра недостающий коэффициент применяет источник. Назначенный коэффициент микшера повторно на источник не накладывается. |
| Настройки | `LocalPlayerSettingsService` хранит проценты и Mute в существующем `ISettingsStore`. Изменения передаются сразу. Запись на диск при закрытии настроек, приостановке или завершении сеанса. Mute сохраняется сразу и оставляет четыре значения прежними. |
| Сброс | `AbilityPlayed` означает, что движок выполнил розыгрыш и перенёс карту в сброс. `AbilityDiscarded` означает отдельный сброс из руки по эффекту. `DiscardAudio` сверяет эти события с изменением публичной стопки между двумя снимками. `TableSync` использует каждый подходящий ID один раз и вызывает `AbilityDiscard` на завершении движения карты. Обычный resync и смена вида в hot-seat обходятся без сигнала. Если отменён только эффект уже сыгранной карты, подтверждённый сброс по-прежнему звучит. |
| Исход битвы | В одном существующем tween победный акцент звучит в начале, групповое выбытие на 34% и уход поля на 67% длительности. Два выбывших существа дают общий сигнал. Ничья или выход из боя не дают победный акцент. Звук поля требует `FieldRemoved`. Дополнительные паузы в очереди отсутствуют. |
| Итог матча | `MatchResultAudio` принадлежит `MatchPresenter`, отдельно от окна. После первой отрисовки он отправляет один `Victory`, `Defeat` или `Draw`. Повторный кадр, решение или повторная отрисовка не воспроизводят его снова. Новый presenter начинает новую партию со своим состоянием. |
| Интерфейс | `UiButtons` отправляет один `Button` при активации доступной кнопки. Смена привязки заменяет прежний callback. `Banner` сопровождает только причину пропуска основного действия, остальные баннеры используют существующие специализированные сигналы. |
| Музыка | `SoundSettings` хранит ссылки меню и матча. Коллекция и поиск используют тему меню. `MusicPlayer` управляет петлями и двумя источниками с плавным переходом. Итог матча переключает музыку на неповторяющуюся заставку, пустая ссылка гасит текущую тему. |

Позиции боевых сигналов рассчитаны для стандартной настройки анимаций. Длина клипов, возможное наложение хвостов, итоговый запас громкости и качество на Android подлежат прослушиванию после производства материалов. Фоновый слой напряжения и варианты звуков остаются в плане производства. [Инструкция по подключению клипов](audio-system.md)

### Проверка реализации

- Unity 6000.6.7f1 скомпилировала проект. EditMode прошёл 372 из 372 случаев, включая 23 новых. Сетевые проверки использовали локальный авторитет и сериализацию кадров получателя.
- В Play Mode подтверждены маршруты четырёх SFX-источников, одного UI и двух Music. Локальная битва прошла через передачу хода, розыгрыш способности и удаление поля. При возврате в меню сохранились тот же `AppRoot` и семь источников, в сцене один слушатель.
- Windows x64 Release содержит `Bootstrap`, `MainMenu` и `Match`. Отчёт сборки содержит 0 ошибок и 0 предупреждений. В Player проверены уровни, Mute, перезапуск и выставление поля против ИИ. В журнале Player есть сообщения UnityTls о проверке сертификата. Проверки через внешний Relay относятся к отдельному прогону.
